# Accessibility and AI use

The browser console uses labeled controls, semantic forms, keyboard-operable buttons, responsive layout, text status updates and error messages. Native desktop controls use Qt. Automated tests do not certify WCAG 2.2 AA. Screen-reader, zoom, contrast, keyboard, mobile and touch-device acceptance remain required before public launch.

Writing and complex tasks are generated by the configured local Ollama model. Direct commands use application code. AI output must be checked for accuracy, permissions and suitability. The interface identifies task status and tool evidence; it does not claim an action solely from generated prose. No always-on microphone is initialized.

If the server or model is unavailable, requests fail visibly. This build does not provide offline browser task execution or silently queue actions for later replay. The desktop's direct local tools can work without model inference.
